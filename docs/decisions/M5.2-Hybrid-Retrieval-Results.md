# BM25 and Hybrid Retrieval Results

**Date:** 2026-10-24.  
**Status:** Implemented and evaluated locally; review required before changing the application default.  
**Design:** [BM25 and Hybrid Retrieval Design](M5.1-Hybrid-Retrieval-Design.md).

The measurements below are the original retrieval experiment. Subsequent graph
and regression findings are in the [final evaluation](M7.1-Final-Evaluation.md).

## 1. Outcome

Hybrid retrieval improves expanded complete-section Recall@5 from **64.67% to 70.44%**, but full evidence coverage remains **6/15 questions**. It regresses on the managed-identity/Key Vault question, still misses the reviewed AKS provisioning sections, and produces one additional full-prompt budget failure. **Keep Chroma dense retrieval as the default.** BM25 and hybrid are explicit experimental strategies; no live answer-generation quality claim follows from these retrieval measurements.

No new dependencies, policy edits, model downloads, provider calls, cloud operations, vector uploads, production reindexing, commits or pushes were performed. The authored Replit/Streamlit offline preview is unchanged.

## 2. Implementation and interfaces

| File | Responsibility |
| --- | --- |
| [catalog.py](../../src/northstar_atlas/vector_store/catalog.py) | Verify saved chunks against the current canonical sources, including metadata, exact primary/context spans and sibling completeness; reject stale fingerprints. |
| [bm25.py](../../src/northstar_atlas/vector_store/bm25.py) | Standard-library tokenization and eligibility-filtered BM25 with positive IDF, `k1=1.2`, `b=0.75`; stable chunk-ID tie-breaking. |
| [hybrid.py](../../src/northstar_atlas/vector_store/hybrid.py) | Dense20 + BM2520, RRF constant60, final five; merge cross-channel IDs, reject within-channel duplicates/corrupt evidence, retain sibling context without extra votes. |
| [contracts.py](../../src/northstar_atlas/vector_store/contracts.py) | Add `RankedHit`, `ScoreContribution` and validated score serialization alongside the unchanged dense `SearchHit`. |
| [preparation.py](../../src/northstar_atlas/vector_store/preparation.py), [pinecone_workflow.py](../../src/northstar_atlas/vector_store/pinecone_workflow.py) | Share the existing read-only frozen-snapshot reader without requiring cloud initialization; preserve the cloud wrapper's validation/error behavior. |
| [context.py](../../src/northstar_atlas/context.py), [generation.py](../../src/northstar_atlas/generation.py) | Accept typed retrieval scores at the context boundary; generation changes are type annotations only. Source, quotation, citation, obligation and budget checks are unchanged. |
| [qa.py](../../src/northstar_atlas/qa.py) | Add explicit `strategy`/`snapshot_id` factory options and strategy diagnostics. Existing defaults and dense call behavior remain compatible. |
| [retrieval.py](../../src/northstar_atlas/evaluation/retrieval.py), [evaluation/hybrid.py](../../src/northstar_atlas/evaluation/hybrid.py) | Reuse frozen scoring with typed score output; run paired local comparisons, candidate diagnostics and offline prompt-readiness checks. |

`load_catalog(root, snapshot_id)` reuses the existing local frozen representation; it does not call the embedding pipeline. `BM25Store.search()` retains the retrieval call shape but never uses its optional embedding-provider argument. `HybridStore.search()` requires the dense provider and supports final `top_k` from 1 to 5. Sibling payloads must already be valid in each channel; fusion cannot repair incomplete results by silently substituting local text.

Tokenization applies NFKC/case-folding and extracts letter/digit runs. Acronyms and numbers survive; punctuation separates terms. There is no stemming, stopword removal, query expansion, per-question boost or parameter tuning. Only positive lexical matches are returned. Corpus statistics use only the mode/date-eligible chunks, preventing draft text from affecting approved-only scores. Source text and chunk IDs remain immutable.

The lexical index is in memory. Missing/stale local snapshots stop setup; nothing is downloaded or regenerated automatically. BM25 can open without MiniLM or credentials. Dense/hybrid use the existing cached MiniLM query encoder. Ordinary questions retain `coverage.status = not_assessed`; retrieval never invents reviewed obligations.

Example offline retrieval usage, after the normal project environment is available:

```python
from datetime import date
from northstar_atlas.project import validate_project_root
from northstar_atlas.qa import open_retriever

snapshot_id = "e55dcdeca17453b27d45f4d3663ef72b9ba3e635f43689899a8d66b52cf27860"
with open_retriever(validate_project_root(), "chroma", strategy="hybrid",
                    snapshot_id=snapshot_id) as (store, embedder, fingerprint):
    hits = store.search("Who approves production access?", embedder,
                        corpus_fingerprint=fingerprint, mode="draft_review",
                        reference_date=date(2026, 10, 22))
```

`open_qa_service()` accepts the same additive options; paid inference still requires its existing explicit opt-in. No UI selection or default was changed. Pinecone remains an optional dense adapter but was not contacted in this task.

These are macro averages using unchanged `complete-source-section-v1`: a reference requires complete canonical source-span coverage. A parent requires its own text and all dot-delimited descendants in the same document. This conservative proxy is not semantic answer adjudication.

| --- | --- | ---: | ---: | ---: | ---: |
| Dense | Direct | 55.22% | 86.67% | 26.67% | 0.6944 |

All arms have zero observed authority leakage or evidence-validation violations.

## 6. Supplementary AKS diagnostic

> An engineer needs temporary production access to troubleshoot an AKS issue. Who should approve it, and which team grants the access?

`draft_review`; all cited policies below remain proposed. Five reviewed diagnostic references: IT-001 §§10.1,9.1 and SEC-001 §§9.1,5.2,6.1. This is separate from the frozen dataset and is not a runtime obligation set.

| Strategy | Direct / expanded coverage | Final direct section references, in rank order |
| --- | --- | --- |
| Dense | 2/5 → 2/5 | IT-001 §10.1; SEC-001 §9.1; SEC-001 §3.1; PLAT-001 §14; another SEC-001 §3.1 chunk |
| BM25 | 1/5 → 1/5 | SEC-001 §3.2; SEC-001 §9.2; SEC-001 §9.1; COMP-001 §10.1; IT-001 §6.2 |
| Hybrid | 2/5 → 2/5 | SEC-001 §9.1; SRE-001 §2; IT-001 §10.1; COMP-001 §6.1; SEC-001 §3.2 |

Dense/hybrid retain Security routing/assessment and temporary-access controls. Neither returns the reviewed direct provisioning sections **IT-001 §9.1 or SEC-001 §6.1**, nor the full distinct-approval section SEC-001 §5.2. Hybrid adds an SRE ownership table that identifies Platform's AKS operations and IT's access coordination, plus Compliance evidence responsibilities. Those are useful context, but they do not replace the explicit cloud permission-mapping, delegated-grant and distinct-approval rules. BM25's emergency-access hit must not be interpreted as proof this question describes an emergency.

Candidate inspection explains part of the failure: SEC-001 §5.2 enters dense candidates at rank9, and SEC-001 §6.1 enters BM25 at rank16. Both lose during final fusion; each has only one channel contribution. IT-001 §9.1 is absent from both top20 lists. Thus reranking could potentially promote some available evidence but could not recover every missing section from this candidate pool. No scores or weights were tuned against this example. No LLM answer was generated, and citation presence does not prove answer completeness.

## 7. Context safeguards and latency

Generation readiness is checked offline using the existing full prompt builder: 32,768 context tokens, 1,024 output reservation and 512 margin. Counts use the existing conservative Qwen byte bound, not billed tokens or MiniLM's 256-token embedding limit.

| Strategy | Mean expanded chunks | Mean expanded characters | Mean / maximum context bound | Full-prompt-ready |
| --- | ---: | ---: | ---: | ---: |
| Dense | 7.40 | 6,761 | 13,369 / 26,245 | 14/15 |
| BM25 | 7.67 | 7,263 | 13,922 / 28,701 | 14/15 |
| Hybrid | 7.87 | 7,435 | 14,160 / 26,592 | 13/15 |

EVAL-006 exceeds the complete prompt budget in all arms. EVAL-010 also exceeds it in hybrid. The evidence-only packages fit, but instructions, schema and question overhead make the full request too large. The existing generator rejects those requests; no mandatory context is silently trimmed. Treating failed preparation as no evidence delivered gives aggregate delivered recall of **58.00% dense, 60.11% BM25, 61.56% hybrid**, separate from the frozen retrieval metrics. Readiness itself says nothing about semantic sufficiency.

Final measured warm retrieval times (45 observations per arm, excluding query encoding and context construction):

| Strategy | Mean | Median | Maximum |
| --- | ---: | ---: | ---: |
| Dense | 19.02 ms | 18.54 ms | 26.22 ms |
| BM25 | 7.67 ms | 7.80 ms | 10.95 ms |
| Hybrid | 40.31 ms | 40.35 ms | 50.89 ms |

These include source/readiness checks, selected payload verification and sibling work. Dense fetches five direct hits, while hybrid fetches twenty dense candidates and their siblings before fusion; this is whole-adapter cost, not isolated search-engine timing. First correctness-pass averages were 19.64, 7.68 and 43.69 ms respectively. Old M2.5 timing included embedding and different audit work and is not directly comparable.

Final model loading took 10.72 s; setup including verification, readiness, model load and all query encoding took 16.95 s. Lexical scorer construction alone took 8.44 ms. Query encoding across all 16 cases averaged 204.39 ms, median 11.82 ms, maximum 3.094 s. These observations are not a controlled cold-machine benchmark. Catalog verification remains bundled with setup; it was not separately timed, so lexical build time must not be presented as complete BM25 startup cost. This minor measurement refinement is deferred.

## 9. Recommendation and limitations

Retain dense retrieval as the MVP default and expose hybrid only through explicit trusted configuration for further experiments. Hybrid improved partial coverage but did not improve full coverage, did not solve AKS provisioning coverage, lowered direct MRR and increased latency/context size. Fifteen synthetic development questions are too few for broad claims, and parameter tuning against them would weaken their value as a stable comparison.

Before any reranking approval, review candidate recall and missing cross-document facets, add separately reviewed paraphrase diagnostics, and address full-prompt capacity without discarding required conditions. Any model download, new dependency, query expansion, family diversification, context-contract change or default switch needs a separate task. No reranker, LangGraph, M6 work, deployment or paid inference was started.
