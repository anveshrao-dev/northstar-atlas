## 10. Implemented service and state ownership

New [orchestration.py](../../src/northstar_atlas/orchestration.py) provides `GraphQAService` and the explicitly selected `open_graph_qa_service()` context manager. The existing `QAService`, answers CLI and Streamlit defaults remain linear. Importing those existing entry points does not require graph packages. No graph selector was added to the UI.

`GraphQAService` accepts trusted stores keyed by `dense`, `bm25` or `hybrid`, an optional embedder, a provider, and a verified `ChunkCatalog`. Its strategy plan contains one or two distinct strategies; the opt-in factory defaults to dense followed by BM25. `ask()` retains the existing question/mode/date/limits/obligation/abstention/extractive-scope arguments and adds an optional caller-reviewed clarification hint. Graph top-k is constrained to 1–5. The public return type remains `QASuccess | QAFailure`.

The five nodes are:

| Node | Responsibility | Failure/branch behavior |
| --- | --- | --- |
| Router | Validate inputs, pin effective-date reference, check catalog currency and bind reviewed requirements against source evidence | Invalid caller configuration fails before retrieval; scoped authored clarification goes to publication |
| Retriever | Invoke the configured strategy with the same question/mode/date/fingerprint and validate every hit/sibling against the catalog | Retrieval errors and invalid source/authority payloads are terminal; no backend switching |
| Evidence assessor | Build a complete evidence package, assess observable availability, and reuse full `prepare_answer()` budgeting and reviewed binding | Empty evidence or absent reviewed chunks may use one alternate; integrity, citation-identity or budget failures stop |
| Generator | Invoke existing `generate_answer()` through a one-call observer | Existing schema, finish reason, model, citation, quote and obligation validation stays in place; no repair or retry |
| Validator | Enforce publication invariants and use shared accepted-public rendering/projection | Only accepted answers or validated authored terminal templates become public; errors expose safe messages |

The graph has typed `GraphState` updates, frozen `GraphRequest`, `EvidenceAssessment`, `AttemptTrace` and `GraphTrace` values. Node updates replace evidence rather than merge attempts. Provider handles and the inference counter live in a per-invocation runtime context, outside graph state. The generator retains only the validated `GroundedAnswer`; raw provider responses and exceptions are not copied into state or public diagnostics. Prepared prompts are internal and tracing is disabled.

The compiled graph is reused; each invocation gets fresh state and counters. `last_trace` is separate, immutable developer diagnostic data containing node names, attempt strategy, chunk/citation IDs, assessment reasons and timing. It contains no source text, prompts, question or rejected candidates. Safe progress is retained in the invocation context so framework/recursion failures cannot erase completed retrieval accounting. It describes the latest **sequential** invocation; concurrent service use is not supported in this initial version.

The small [qa.py](../../src/northstar_atlas/qa.py) refactor shares accepted-public projection and prepared/accepted diagnostics. The existing text and structured presentation remain unchanged. Its observed provider has an optional one-call guard used by the graph; linear QAService behavior remains unchanged.

## 11. Safety, evidence assessment and lifecycle

- **Two retrieval attempts maximum, one inference maximum.** An alternate replaces the entire previous evidence set. Hybrid's internal dense20/BM2520 searches are channels within one store attempt, not a promise of one underlying network request. Graph nodes have no retry policy, cache, checkpoint or resume path. A fixed recursion limit of 10 protects the bounded seven-node longest route.
- **Reviewed configuration is not retrieved evidence.** The graph requires a verified catalog even for dense-only plans. A temporary source package authenticates caller citations, quotes, scope and spans before retrieval; it is never merged into retrieved context. Missing valid reviewed sources can trigger the alternate; fabricated/stale requirements cannot. Exhausted reviewed requirements produce a context error, not a stripped-requirement answer.
- **Ordinary coverage remains `not_assessed`.** Nonempty eligible evidence that fits the complete prompt can proceed, without claiming semantic sufficiency. Scores never decide authority or semantic completeness. No Terraform, retention or dataset answer-key rules are embedded in runtime routing.
- **Fail closed on malformed adapter output.** A known draft/future-effective hit returned for approved-only is a context error, as are changed hashes, extra/missing siblings, source gaps, mismatched model provenance and invalid grouping. This stricter graph adapter boundary does not alter the linear service's existing filtering behavior.
- **Clarification and abstention stay distinct from errors.** Trusted clarification hints are question/mode-scoped, contain no policy guidance, and cannot bypass reviewed obligations. Two empty attempts produce the existing validated no-evidence abstention with zero inference calls. A documented gap still needs caller-reviewed limitation requirements, retrieved evidence, citations/quotations and the existing generation contract. Infrastructure failures never become policy abstentions.
- **Prompt budgets remain intact.** The assessor may repeat pure context construction through `prepare_answer()` and checks package equality. It never repeats retrieval for this check, truncates siblings, removes reviewed conditions, or uses MiniLM's input limit as an LLM budget. Defaults remain 32,768 context / 1,024 output / 512 margin; the separate UI's explicit configuration is unchanged.
- **No automatic tracing or actions.** Invocation runs in fresh context variables with scoped LangSmith tracing disabled, empty callbacks, no external runtime configuration, no SDK clients and no checkpoint store. Tests block sockets and assert that tracing flags and inherited callbacks cannot export graph data. No tools, autonomous actions, query rewriting, agent loop or additional model grader were introduced.
- **Providers and catalogs are trusted integration dependencies.** The factory configures Nebius with `max_attempts=1`; retry-enabled existing providers are rejected before backend setup. The observer prevents a second `generate()` call and rejects a response reporting multiple attempts. It cannot inspect arbitrary caller-written provider internals; such providers must honor the single-transport-attempt contract.

The factory requires an explicit existing immutable local `snapshot_id`; it neither discovers another target nor creates a missing snapshot/index. It validates current corpus/model identity, shares one dense adapter/embedder with hybrid, and uses one verified local catalog for lexical retrieval. Pinecone remains explicitly selectable through the existing opener and confirmation/readiness checks. It was not contacted in this task. `ExitStack` closes only factory-owned resources; injected providers remain caller-owned, and safe setup errors do not expose credential or cleanup exception text.

## 14. Phase B semantic-checking profile — 2026-10-25

This historical checkpoint predates Phase C1 and controlled-live wiring. Its test
results and then-pending integration work are preserved below; see section 15 for
the implemented follow-up.

The approved Phase B design is implemented as the versioned, opt-in
`llm_routing_grading_semantic_v1` profile. It reuses Phase A routing and batched
relevance grading, then applies the existing deterministic generation contract
before a semantic check. The generated candidate is published only if the
semantic check returns a complete `supported` assessment and final deterministic
publication checks pass. Linear `QAService`, `bounded_v1`, Phase A's
`llm_routing_grading_v1`, existing retrieval defaults and Streamlit behavior are
unchanged. The new profile is not connected to Streamlit.

Phase B changes in this task:

- Updated `src/northstar_atlas/orchestration.py` with the opt-in graph state,
  semantic-check node and conditional regeneration route.
- Extended `src/northstar_atlas/orchestration_assessment.py` with the public-text
  inventory, strict semantic response contract, normalized issue codes,
  same-evidence regeneration request builder and Phase B call ledger.
- Extended `tests/test_orchestration_assessment.py` and added
  `tests/test_orchestration_semantic.py` for the contract, transition and
  compatibility regressions.
- Updated this implementation report.

The application constructs a semantic inventory from validated public fields:
claims, resolved obligation statements, visible unresolved-obligation reasons,
clarification questions and missing-information entries. It checks support,
policy authority, conditions, question-level completeness relative to admitted
evidence, and how unresolved gaps are represented. These are separate from
caller-reviewed obligation coverage; ordinary-query obligation coverage stays
`not_assessed`. The inventory and full candidate/evidence package are supplied
to the checker as data, not instructions. A checker judgment is a probabilistic
review signal and cannot prove semantic faithfulness or discover evidence that
retrieval did not supply.

Generated clarification and abstention text is checked, including text in
`missing_information`. Semantic checking is skipped only for the exact trusted
application-authored no-evidence abstention template and a question/mode-bound,
caller-reviewed neutral clarification. Deterministic source, policy-mode,
citation, quotation, status and reviewed-obligation checks remain mandatory
before and after the semantic step. Abstention rendering omits unresolved
per-obligation reasons; a regression test ensures those hidden strings are not
sent to the checker, while visible unresolved reasons in other answer kinds are
assessed.

Routing behavior follows the approved state machine:

| Event | Result |
| --- | --- |
| Deterministic generation/schema/citation/quotation/eligibility/obligation failure | Withhold before semantic checking; no regeneration |
| Complete semantic `supported` result | Proceed through final deterministic publication validation |
| Complete `unsupported` or `incomplete`, with no unclear judgment | One regeneration using the same question, context, mode and reviewed obligations; run deterministic validation and a second semantic check |
| Any `unclear`, including mixed negative/unclear results | Terminal rejection; no regeneration |
| Malformed/incomplete checker output or provider failure | Terminal safe failure; no regeneration |
| Second negative result or deterministic failure after regeneration | Withhold; never convert exhaustion to an answer or policy abstention |

The Phase B workflow enforces the approved seven-call maximum: one router, up to
