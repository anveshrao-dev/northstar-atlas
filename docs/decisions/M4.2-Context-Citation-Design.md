# Evidence Context and Citation Builder

> Historical engineering record. Proposals, scope limits and dated measurements
> describe the work at that time, not current setup or operational authorization.
> See the [current architecture and experiment guide](../README.md) and
> [project README](../../README.md) for the implemented system and remaining limits.

**Scope:** Offline context preparation and deterministic citation membership validation. No LLM client, answer generation, retrieval changes, new dependencies or tokenizer downloads.

## 1. Purpose and architecture

`build_context` consumes the shared `SearchHit` values already returned by Chroma and Pinecone. It does not query either backend, initialize an embedding model, read credentials, or access the network. The caller remains responsible for using the existing verified retrieval path, corpus fingerprint and compatible model configuration.

The [M2.5 baseline](M2.5-Retrieval-Evaluation.md) and [M3.4 comparison](M3.4-Chroma-Pinecone-Comparison.md) demonstrate why complete context matters: expanded section coverage improved, but remained incomplete for many questions. This builder preserves supplied evidence; it cannot discover missing cross-policy rules. The fifteen evaluation questions and their forty required references remain evaluation inputs, never runtime prompt content.

New files:

- `src/northstar_atlas/evidence.py`: typed immutable evidence values, token-counter contract, citation formatting and validation.
- `src/northstar_atlas/context.py`: eligibility checks, required-context closure, exact span deduplication, grouping, rendering and budgeting.
- `tests/test_context.py`: deterministic offline fixtures and boundary tests.
- This design note. No pre-existing source file needs modification.

## 2. Data models and interfaces

| Model | Responsibility |
| --- | --- |
| `EvidenceSource` | Retains the complete original `PolicyChunk` or `RefinedPolicyChunk`, exact `TextSegment` mappings, required sibling IDs and direct rank if present. Siblings have no invented retrieval rank. |
| `EvidenceSpan` | An exact contiguous source excerpt, end-exclusive character offsets and contributing chunk IDs. |
| `EvidenceGroup` | One document snapshot and section, its sources/passages, earliest direct rank, citation and the number of duplicated source characters removed. It is an indivisible budget unit. |
| `ContextPackage` | Included groups, warnings, mode/reference date, exact rendered JSON, counted size, budget and counter identity. |
| `CitationReference` | Stable reference ID, document/section, version/status, source hash and contributing chunk IDs. |
| `ContextWarning` | Structured reason and affected IDs for exclusions, source gaps, unrelated context, missing context or empty input. Critical warnings accompany `ContextError`; no partial package is returned. |
| `ContextTokenCounter` | An injected `name` and `count_tokens(text) -> int`; there is no implicit tokenizer or approximation. |

Main entry point:

```python
package = build_context(
    hits,
    counter=generation_token_counter,
    max_tokens=evidence_budget,
    reference_date=reference_date,
    mode="approved_only",
)
```

`generation_token_counter`, `evidence_budget` and `reference_date` are explicit caller inputs. This example does not instantiate or approve a hosted tokenizer.

## 3. Assembly and evidence grouping

1. Check input settings, chunk metadata, tracked text spans and consistent embedding provenance. Identical repeated chunk IDs collapse; conflicting payloads under one ID fail.
2. Apply authority filtering to direct hits. `approved_only` admits only approved policies effective on the explicit date; excluded drafts/future approvals receive warnings. `draft_review` preserves approved and proposed sources, including their effective-date metadata.
3. Follow required sibling IDs through the supplied result/context pool. A sibling may also be another direct hit. Missing or incompatible required siblings fail the entire operation before budgeting. Extra unrelated context cannot introduce a new evidence source.
4. Reuse the existing pure `validate_context` family checks and refiner `reconstruct` validation. Every refined family must have a complete primary-span partition, consistent provenance and context text matching that partition. This checks internal consistency; authenticating text against disk/manifest remains the verified retriever's responsibility.
5. Group by document and section after rejecting mixed document snapshots. Within a section, order sources by source location, then merge contiguous or overlapping exact spans. Overlapping characters must agree. Keep identical sentences at different offsets or in different documents: those may be distinct rules.
6. Preserve disconnected excerpts as separate passages and report `source_gap`. Do not concatenate them as if the missing text never existed. A citation to a section does not assert that its entire section or descendants were retrieved.
7. Serialize deterministically as JSON with separate `approved_evidence` and `proposed_evidence` arrays. Include headings, citation labels, status, effective-date indicator, source hash/path, original segment mappings, sibling IDs and source passages. Escaping keeps policy text inside data fields; source text remains untrusted.

Two bounded refinements to [M4.1](M4.1-LLM-Provider-Design.md) implement this task's requirements: references are hash-based instead of rank-dependent `E1` aliases, and duplicate source spans are removed once a complete family can be reconstructed. The original chunks and their duplication mappings remain available in `EvidenceSource`; source meaning is not paraphrased. The alternative of keeping every repeated fragment is simpler but uses more context. Deduplication by similar wording would risk deleting meaningful qualifications and is deliberately avoided.

## 4. Token budgeting

`max_tokens` is an **evidence-package budget**, not the generation model's total context window and not MiniLM's 256-token embedding limit. The generation layer must reserve room for instructions, user question, schema, chat framing and output, then validate the final complete request with its model-specific counter.

The builder counts the entire rendered JSON each time it considers adding a group. This includes labels, headings, status, provenance, JSON syntax and any text repetition that remains. It does not add per-chunk counts, because tokenization across boundaries need not be additive.

Groups are considered in earliest direct-rank order. A group that cannot fit is excluded in full with `budget_excluded`; later smaller groups may still fit. There is no summarization, truncation, sentence cutting or orphan sibling. Even the empty envelope must fit, otherwise construction fails. Counter exceptions or nonpositive/noninteger results also fail clearly. Warnings are out-of-band diagnostics, not additional citable prompt content.

No generation tokenizer was available or downloaded for M4.2. Tests use `fixture-characters-plus-two`: one unit per character plus two wrapper units. This provides exact, deterministic boundary assertions, **not Qwen/Nebius token counts**. The library requires a counter rather than presenting whitespace or MiniLM counts as generation-token accounting. A future approved tokenizer adapter must supply a stable identifier and compatible counting behavior.

## 5. Citations and validation boundary

`format_citation` emits a stable machine reference plus human label:

```text
[ev-<64 hexadecimal characters>] PLAT-001 v0.1 §6.1 (proposed)
```

The full hash incorporates document, version, status, source hash/path, section and sorted contributing chunk IDs. It remains stable when ranks or budgets change with the same evidence membership; source/membership changes create a new reference. The human label stays readable and preserves approval status.

`citation_syntax_valid` checks only the explicit marker grammar. `validate_citations` accepts structured `CitationReference` values or full formatted markers and resolves them against included groups in the trusted package. It rejects invented IDs/sections, altered versions/status/hashes/chunk membership, malformed markers, and references excluded by filtering or budget. Duplicate valid references collapse in first-use order. Bare section names or rank-dependent aliases are intentionally insufficient.

**Membership is not semantic support.** A syntactically correct citation may be invented; a valid supplied citation may still be attached to an incorrect claim. This component does not parse generated answers, verify supporting quotations, decide clarification/abstention, or assess answer faithfulness. Those remain later generation/answer-evaluation work. Citation validation trusts the immutable package produced by the builder, not a caller-reconstructed or LLM-authored package.

## 6. Missing evidence and limitations

- Missing required sibling context raises `ContextError` with the missing ID. Invalid sibling identity/eligibility likewise fails; no partial evidence is returned.
- Excluded direct hits, unrelated supplied context and budget-excluded groups receive explicit warnings. An empty or entirely ineligible result still has a valid empty package if its envelope fits.
- Warning-free output means only that these structural checks passed. It does not establish that retrieval found all evidence needed for the question. The generation layer must inspect warnings and apply conservative answer behavior.
- Sibling relationships currently belong to the same canonical family/section. Cross-document or cross-section prerequisites are not inferred from prose. Unsupported relationships fail validation rather than being silently followed.
- Stable source hashes are provenance, not independent proof that an arbitrary caller's text is authentic. Use the existing verified retrieval path; this pure component deliberately performs no filesystem or index audit.
- JSON escaping and an untrusted-content label help maintain boundaries but do not guarantee resistance to prompt injection. No executable tools or generation capabilities exist here.
- This implementation retains all source metadata in original chunk values. Rendered evidence exposes only the selected provenance/authority fields, not vectors, credentials or absolute machine paths.
- **Deferred minor from independent review:** manually constructing a `SearchHit` with a non-chunk `chunk` field or a nonnumeric distance can raise `AttributeError`/`TypeError` before normalization to `ContextError`. The documented input is verified, typed retrieval output; those normal paths are covered. Broader defensive error normalization remains future polish, not a claim that arbitrary untyped input is supported.

## 7. Terraform example

The checked example uses the actual verified PLAT-001 §6.1 text in **two hand-built retrieval fragments**, with a repeated heading. These are deterministic test fixtures, not a claim about the number or IDs of persisted MiniLM records.

| Inspection | Actual result |
| --- | --- |
| Citation | `PLAT-001 v0.1 §6.1 (proposed)` |
| Included groups / source fragments | 1 / 2 |
| Source text | All 2,090 characters reconstructed exactly |
| Repeated source characters removed | 43 |
| Count / budget | 4,119 / 10,000 **fixture units**, not model tokens |
| Warnings | None |
| Artifact | `.local/m42/terraform-evidence.json` (ignored) |

The same group retains the authorized Platform review requirement, the restriction on the normal-change plan author reviewing their own work, Change Management's reliance on technical evidence, renewed technical approval after regeneration, and the condition that no separate Change Management approval is required solely for regeneration while scope/risk/window/other approval conditions remain satisfied. The stop/amendment/escalation condition remains present as well.

This is a description of a **proposed synthetic policy**. If the group cannot fit, neither half is supplied and its citation is rejected. The test checks both exact reconstruction and these specific conditions' presence; it does not claim that a future LLM will interpret them correctly.

## 8. Validation and Generation Interface

The initial 27 focused tests were observed failing because the builder did not exist, then passed after implementation.

- **225 tests passed, no failures or skips, in 86.339 seconds:** 198 existing tests plus 27 new context tests. Cached MiniLM checks were enabled offline; no models were downloaded or live cloud clients used.
- **M1.8 validator passed:** fifteen unique questions, category counts 3/6/3/3, pinned source/manifest hashes, evidence sections, modes and expected behaviors.
- Independent read-only review reran the 27 focused tests and found no Critical or Important issues. The single deferred minor is documented in §6. Hosted token accuracy and generated-answer semantics are outside this component; source authenticity is explicitly the verified retriever's responsibility. Incorrect upstream verification or tokenizer accounting would invalidate downstream guarantees, so the generation layer must retain those boundaries.
- SHA-256 comparison confirmed all **76 pre-existing files** in the captured source, tests, policy/data, evaluation, script, documentation, configuration and Git-index/HEAD snapshot remained unchanged. Exactly the four files listed in §1 were added. Git staging and HEAD were preserved.
- Markdown fences and relative links validated. Logs, the Terraform fixture artifact, plan and preservation snapshot are confined to ignored `.local/m42/`. No dependency/model download, network/API operation, policy change, commit or push was performed.

Validation commands from the authorized root:

```bash
PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.local/tmp" \
  HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 NORTHSTAR_RUN_MODEL_TESTS=1 \
  .venv/bin/python -B -m unittest discover -s tests
.venv/bin/python -B scripts/validate_evaluations.py
```

The generation layer can inject either retriever, call `build_context`, inspect warnings, and put only `package.rendered` into the untrusted evidence portion of the request. It must independently budget the complete request, use only the package's allowed references, and validate returned citations against that same package before rendering. Provider calls, supporting-quote/claim checks and generated answer behavior are outside this component.
